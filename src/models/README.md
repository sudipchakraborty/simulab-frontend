# Portable models and educational robotics

`ComponentModel.update(timeUs,pins)` is independent of React and CPU engines. `createExpandedModel(component,opticalBus)` supplies parameterized sensor/robot models; callers can replace any kind through `CircuitRuntime` factories. Every circuit host gets a separate optical bus. Never share stateful instances across circuit runs.

## Electrical and mechanical scope

- `solveDc` solves ideal voltage sources, positive linear resistors, electromagnetic winding resistances and ammeter shunts. Each resistive island has a maximum256 unknown nodes. Floating, source-conflicting, singular, invalid-resistance and oversized islands return unknown values rather than invented readings. A voltmeter is an ideal zero-load differential probe; ammeter current is signed POS to NEG through its explicitly configured shunt. This is a DC linear solution, not SPICE, nonlinear LED current, motor supply load, AC, transient, inductance or mains safety analysis. The legacy digital LED projection intentionally remains separate and explicitly labeled.
- `StepperDriver` requires logic supply, motor supply, ground, active-low EN, actual STEP rising edges and valid DIR. Ideal one-phase full-step winding outputs drive `StepperMotor`; over-rate steps are refused. Direct MCU GPIO winding/coil power is refused by the circuit host. Driver current regulation, microstepping, torque and inertia are not modeled.
- Servo/arm joints decode actual1000..2000us pulses and slew to the bounded target only after pulse completion. The ideal command is latched until the next valid pulse; loss-of-pulse watchdog, load and holding current are not modeled.4.5..6V power is required. Parameters specify approximate speed and joint range.
- Electromagnetic switches expose independent COIL_POS/COIL_NEG and isolated COM/NO/NC. Rated voltage, DC winding resistance and response delay are configurable; flyback/transient and contact-current protection are not modeled. Tactile switches have permanently paired1A/1B and2A/2B leads; pressing joins the pairs.
- Robot arms share one parameterized class. Generic6DOF and generic Universal-style profiles have six bounded PWM joints. Dobot Magician/uArm Metal educational profiles have four. Base yaw and planar shoulder/elbow links determine tool position; wrist angles provide an approximate orientation report. All link lengths, limits and SVG geometry are educational assumptions, including named profiles. These are **not manufacturer-certified geometry, vendor controller/USB/serial protocol implementations, collision/IK or dynamics models**.
- Conveyor and four-wheel skid-steer car include explicit powered driver inputs. EN and direction inputs drive deterministic no-slip kinematics. Wheel slip, collisions, inertia and payload are absent. IR modules communicate through matching optical channel IDs plus explicit metre coordinates, range and obstruction; canvas placement does not create optical or electrical connections.

## Sensor protocol evidence and boundaries

HX711 follows MSB-first24-bit clocking,25/26/27 pulse A128/B32/A64 selection,10/80Hz readiness and >60us clock-high power-down/reset from the [AVIA HX711 V2.0 manufacturer datasheet](https://www.mouser.com/datasheet/2/813/hx711_english-1022875.pdf). `rawValue` is an ideal signed scene sample at A128; A64 scales it by one half, while `rawValueB` is the independently supplied B32 sample. Noise, bridge excitation, calibration drift, settling, submicrosecond pin propagation and analog precision are not claimed.

DHT22/AM2302 models signed temperature and humidity tenths,40-bit checksum frames, open-drain response timing and a2-second read interval. It needs a wired external pull-up resistor and simulation-clock input reads. Device identity/interface reference: [ASAIR AM2302](https://asairsensors.com/product/am2302-dht22-temperature-and-humidity-sensor/); frame timing reference: [Aosong AM2302 product manual](https://www.aosong.com/uploadfiles/2025/04/20250417105409216.pdf). Power-up warm-up, sensor aging and measurement acquisition physics are not modeled.

The real compiled `fixtures/robotics-sensors.c` ATmega328P fixture clocks HX711 -2 and then reads DHT22 -12.3C/60% through actual GPIO input instructions. `sensorFirmware.test.ts` verifies UART bytes `48 FF FF FE 44 02 58 80 7B 55`, including the DHT checksum. It uses circuit voltage resolution and engine instruction-clock callbacks, with no manual sensor byte injection. Compiler command and hashes are recorded alongside the HEX. Physical hardware comparison has not been performed. AVR host integration must invoke `advance` on GPIO changes and before input reads; coarse snapshots cannot decode timed protocols. ESP32-S3 snapshot-based timed-device interoperability remains explicitly unverified.

## Board/schema integration

`boardRegistry.ts` exports MCU kinds, target mapping, native AVR header metadata and I2C pins. Nano uses real ATmega328P execution supplied by the engine; A6/A7 are ADC-only and explicitly unsupported because ADC conversion is absent. Mega uses native D0..D53/A0..A15 and D20/D21 I2C, requiring a distinct ATmega2560 engine profile. All AVR clocks are16MHz. Schema1.3 introduces these catalog kinds and preserves1.0/1.1/1.2 loading. Known model parameters are bounded during import and Inspector editing; unknown extension properties remain portable.
